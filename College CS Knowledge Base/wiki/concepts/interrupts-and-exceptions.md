Interrupts and exceptions are the mechanisms by which the CPU transfers control to the OS in response to events — whether from external hardware, internal CPU faults, or deliberate software traps. Together they allow the OS to respond to the real world (I/O) and enforce security and correctness (memory faults, illegal instructions, system calls).

## Taxonomy

All four types share a common mechanism: the CPU saves state (flags, CS, RIP) on the kernel stack and jumps to a handler address from the interrupt vector table (IVT).

| Type | Trigger | Sync/Async | Return Behavior |
|------|---------|-----------|-----------------|
| **Hardware Interrupt** | Signal from I/O device (timer, NIC, keyboard) | Asynchronous | Return to next instruction |
| **Fault** | Unintentional but recoverable CPU error | Synchronous | Maybe return to *current* instruction (retry) |
| **Abort** | Severe, unrecoverable error | Synchronous | Does not return |
| **Trap / System Call** | Intentional `INT` or `syscall` from user code | Synchronous | Return to next instruction |

## Hardware Interrupts

Generated by I/O devices (keyboard, timer, network card) at any time, regardless of what the CPU is executing. Guaranteed to be taken on an **instruction boundary** (an instruction completes before the interrupt is handled). The handler:
1. Saves all registers.
2. Services the device.
3. Restores registers.
4. Executes `iret` (restores flags, CS, RIP).

## Faults

Faults occur during instruction execution. After the handler runs, %rip points back to the **faulting instruction**, which is retried. Common faults:

- **Page fault (exception #14):** A virtual address is accessed but its page is not currently mapped. The OS allocates a physical page, updates the page table, and the instruction succeeds on retry.
- **Segmentation fault (exception #13):** A virtual address is accessed that is not in any valid mapping. OS sends `SIGSEGV`.
- **Divide error (exception #0):** Division by zero for integers (SIGFPE). Floating-point divide-by-zero may yield +∞ instead (IEEE 754).

## Aborts

Aborts are severe errors from which the system cannot recover (e.g., memory parity error, machine check, ECC checksum failure — exception #18). The current program is killed and control is handed to the OS.

## Traps (System Calls)

A trap is a synchronous interrupt intentionally generated by the user program to request OS services. On x86-64 Linux: `syscall` instruction. The IVT ensures the program can only enter the kernel at OS-defined entry points.

## Intel Exception Table (selected)

| Number | Type | Description |
|--------|------|-------------|
| 0 | Fault | Divide error |
| 3 | Trap | Breakpoint (INT 3) |
| 13 | Fault | Segmentation fault (General Protection) |
| 14 | Fault | Page fault |
| 18 | Abort | Machine check |
| 32–127 | Interrupt or Trap | OS-defined |
| 128 | Trap | Legacy system call (INT 0x80) |
| 129–255 | Interrupt or Trap | OS-defined |

## Interrupt Handler Protocol

The Linux interrupt handling protocol:
1. CPU saves `%rflags`, `%cs`, `%rip` onto the kernel stack.
2. CPU jumps to the handler address from the IVT.
3. Handler saves all registers (must not change registers before saving).
4. Services the interrupt.
5. Restores all registers.
6. Executes `iret`.

## Signals as OS-Level Delivery

The OS can deliver exceptions to user processes as [[Process Attributes|signals]]. Signals are the user-space analog of exceptions:
- `SIGSEGV` — segmentation fault (exception #13/14 → signal).
- `SIGFPE` — arithmetic exception.
- `SIGILL` — illegal instruction.
- `SIGCHLD` — child process terminated.
- `SIGINT` — Ctrl+C terminal interrupt.
